# Batch Creation Error Fixed

## Problem
When trying to create a batch in the Batch Management page, the operation failed with:
```
Error: Failed to create batch
POST /api/batches 500
```

Backend error:
```
Error creating batch: {
  code: 'PGRST201',
  message: "Could not embed because more than one relationship was found for 'batches' and 'products'"
  hint: "Try changing 'products' to one of the following: 'products!batches_product_id_fkey', 'products!fk_batches_product'"
}
```

## Root Cause
The `batches` table has **two foreign key constraints** pointing to the `products` table:
1. `batches_product_id_fkey` (auto-generated by PostgreSQL)
2. `fk_batches_product` (manually created)

When the backend tried to return related product data after creating a batch, Supabase/PostgREST couldn't determine which relationship to use, causing the PGRST201 error.

## Solution
Updated the batch controller to use **explicit foreign key names** in the `.select()` queries:

### File: `backend/src/controllers/batchController.js`

**Function: `createBatch()`**
```javascript
// BEFORE (ambiguous):
.select(`
  *,
  products (id, sku, brand, model, dimensions),
  shipments (id, shipment_number, container_number)
`)

// AFTER (explicit):
.select(`
  *,
  products!fk_batches_product (id, sku, brand, model, dimensions),
  shipments!fk_batches_shipment (id, shipment_number, container_number)
`)
```

**Function: `updateBatch()`**
```javascript
// BEFORE (ambiguous):
.select(`
  *,
  products (id, sku, brand, model),
  shipments (id, shipment_number)
`)

// AFTER (explicit):
.select(`
  *,
  products!fk_batches_product (id, sku, brand, model),
  shipments!fk_batches_shipment (id, shipment_number)
`)
```

## Why This Happened

### Background
During database migrations, two foreign key constraints were created:

1. **Auto-generated** by PostgreSQL when using `REFERENCES`:
   ```sql
   ALTER TABLE batches ADD COLUMN product_id UUID REFERENCES products(id);
   -- Creates: batches_product_id_fkey
   ```

2. **Manually created** in migration script:
   ```sql
   ALTER TABLE batches 
   ADD CONSTRAINT fk_batches_product 
   FOREIGN KEY (product_id) REFERENCES products(id);
   ```

Both constraints are functionally identical but have different names. PostgREST sees both and can't decide which one to use for embedding related data.

### Long-term Solution (Optional)

You can remove one of the duplicate constraints to prevent future confusion:

```sql
-- Check existing constraints
SELECT conname, contype 
FROM pg_constraint 
WHERE conrelid = 'batches'::regclass 
AND contype = 'f';

-- Remove duplicate (keep fk_batches_product)
ALTER TABLE batches DROP CONSTRAINT IF EXISTS batches_product_id_fkey;

-- Verify only one remains
SELECT conname FROM pg_constraint 
WHERE conrelid = 'batches'::regclass 
AND conname LIKE '%product%';
```

**Note:** This is optional. The explicit FK name approach in the code works fine even with duplicate constraints.
